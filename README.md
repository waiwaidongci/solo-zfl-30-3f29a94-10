# 水下考古潜次合规封存与复查台

离线单页应用，无需服务器、无运行时第三方依赖：直接用现代浏览器打开 `index.html` 即可使用
（`file://` 直开已验证；SHA-256 校验码使用浏览器内置 Web Crypto）。

在原「离线水下考古记录页」基础上扩展，保留地图标记旧入口，并新增潜次合规封存、只读快照、
追加复查、快照还原与审计导出。

## 功能

- **合规封存**：潜次结束前按人员、气瓶、深度、时长、天气、归属逐项检查；
  缺项、超限（默认深度 40m / 时长 60 分钟）、标记重号、跨潜次引用未封存潜次等**一律拦截封存**，
  警告（如雾/小雨、引用已封存潜次）列出但不拦截。
- **只读快照 + 校验码**：检查通过后封存，生成规范化 JSON 的 SHA-256 校验码（前 12 位展示），
  封存的潜次信息与原标记只能查看，编辑/删除按钮禁用，地图以虚线显示。
- **复查只能追加**：复查记录逐条追加，带哈希链（封存校验码为链根，任意改写即断链）；
  观测行只能引用该潜次**封存快照内**的标记编号（快照外编号一律拒绝，差异表不会出现伪「新增标记」）；
  原封存快照永不改动；差异比较按「保存状态」等字段给出封存时→复查后变化，观测说明单列。
- **坏版本/坏文件不丢数据**：
  - 每次写入后回读校验，通过才提升为「最近完好备份」，主档损坏自动从备份恢复；
  - 坏 JSON、未来高版本、导入坏文件/校验失败的审计包——**只隔离原文，绝不覆盖现有数据**；
  - 还原快照、导入前，当前完整状态自动写入隔离区保底；
  - 数据与审计视图可查看/导出隔离区原文。
- **审计包**：导出含完整状态、每个封存的复算结论、复查链结论与包级 SHA-256；
  导入时先复算包级校验码与每个封存快照，并**逐条验证复查哈希链及观测编号是否在快照内**——
  即使改写复查内容后重算整包校验码，链断裂与快照外编号仍会被识别；坏包只隔离、不覆盖现有数据。
- **同步**：地图、标记列表、潜次时间线、封存/复查入口共用同一数据层，状态实时同步。
- **桌面与手机**：响应式单列布局；手机视口下封存、复查、恢复、导出均已走通。

## 目录结构（数据层与界面分离）

```
index.html              界面结构与样式
js/crypto-util.js       规范化 JSON / SHA-256 / UUID（UMD）
js/rules.js             合规规则（纯函数，可独立测试）
js/store.js             封存/复查/备份隔离/还原/审计包（UMD，不依赖 DOM）
js/app.js               界面层，只通过 Store 读写
test/store.test.js      Node 原生 test runner 数据层测试（40 项）
test/browser.test.js    Playwright 真实浏览器检查（桌面+手机，48 项）
docs/browser-checks.md  真实浏览器检查记录与截图说明
```

## 自动化测试

```bash
npm test                 # Node 数据层测试（node --test，40 项）
npm run browser-test     # 真实 Chromium 端到端检查（需 npx playwright install chromium）
```

浏览器检查结果见 `docs/browser-checks.md`（2026-09-13：48/48 通过，含桌面 1440×900 与手机 390×844）。

`tools/fetch-chromium-deps.js` 仅供无 root 的 Linux 抓取 Chromium 运行库到 `tools/sysroot`，
与应用运行无关。
